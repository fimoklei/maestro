## Tentative

Single observations. Consider but do not auto-apply. Promote to Active on reconfirmation.

- **2026-07-19 · apm/rich-wraps-phrases-mid-sentence** — apm's install output is Rich-rendered, so it hard-wraps at terminal width *inside* a sentence. The captured symlink refusal (`tests/fixtures/apm-install-symlink-refused.txt`) breaks as `... /skills/tdd is` / `a symlink -- refusing to deploy`, so a literal `includes("is a symlink")` on the raw output silently misses — the classifier reads a diagnosed refusal as a generic failure, and a hand-typed one-line test fixture would hide it. Unlike `apm outdated`, the install path sets no fixed `COLUMNS`, so the wrap point is not controllable. → Match any apm phrase against whitespace-normalized output (`text.toLowerCase().replace(/\s+/g, " ")`), and build fixtures from a real capture, never retyped.
- **2026-07-19 · tooling/commit-gate-lints-whole-tree** — The commit-gate hook runs `pnpm lint` (= `biome check .`), which scans the entire working tree, not the staged diff. A docs-only commit (`docs/jobs.md`) was blocked by two lint errors in an **untracked, unstaged** scratch file (`packages/web/prototype-register-outcomes.html`) that had nothing to do with it. Biome's `useIgnoreFile: true` does not help: untracked-but-not-gitignored files are still scanned. Prototypes are now excluded via `!**/prototype-*.html` in `biome.json`, but any other stray file reproduces this. → When the gate fails on files outside your staged diff, do not "fix" someone else's work-in-progress to get past it. Check `git status --short` first; either gitignore/exclude the stray file class, or ask before touching it.
- **2026-07-18 · tooling/sibling-worktree-port-squat** — This machine keeps multiple sibling git worktrees for this repo (one per issue branch, e.g. `maestro-148`, `maestro-149`). `pnpm smoke`'s single-instance guard is scoped to the worktree it runs in (PID file local to that checkout) — it does not detect or evict a dev server left running from a *different* worktree. All worktrees default to the same ports (3000/5173), so a stray server from another worktree can keep holding the port; a browser driven against `localhost:5173` may then be looking at the wrong branch's UI while `pnpm smoke` in the current worktree believes it started cleanly. Caught via `lsof -i :5173` showing a `vite` process whose cwd was a sibling worktree, not the current one. → Before trusting any browser-based screenshot/verification against `localhost:5173` or `:3000`, run `lsof -i :5173 -i :3000` and check the owning PID's cwd (`lsof -p <pid>`) matches the current worktree; kill and restart if not.
- **2026-07-16 · process/owner-cant-recount-it-its-dead** — The job map + roadmap + coverage instrumentation grew past what the owner could retell from memory (he had to ask what his own "Imp/Sat" column and "step-grill" term meant); a process artifact the owner cannot hold in his head is dead ceremony, however sound its principles. Replaced by one board (`docs/jobs.md`, its Legend the transition rules) driven by the `jobs` skill. → Before adding any process artifact, rule, or ritual: it must hang on a moment that already exists (grill start, `/to-spec`, the ship PR) and the owner must be able to retell it; otherwise do not add it.
- **2026-07-13 · apm-driver/stale-sandbox-false-unverifiable** — A Global deploy showing "This copy predates content tracking" (`deployed-unverifiable`) can be a **stale smoke sandbox**, not a live bug. Symptom seen: the sandbox's skill sat as a `name: home` apm project at HOME-root (`<sandbox>/home/apm.yml` + `apm.lock.yaml` + `apm_modules/`) with `.apm-scratch` absent — the shape of a per-repo install rooted at HOME, which the current `-g` path never produces. Verified by running Maestro's exact command (`apm install <ref> -g -t claude,codex`, cwd=`MAESTRO_HOME/.apm-scratch`, smoke env): apm 0.20.0 lands cleanly in `~/.apm/apm.lock.yaml` with `deployed_file_hashes`, nothing at HOME-root, scratch cwd stays empty. `resolveApmGlobalRoot` → `~/.apm/` matches that, so a clean deploy classifies clean. Absent `.apm-scratch` = the `-g` path never ran. → Before chasing an unverifiable-Global as a code bug, restart `pnpm smoke` (wipes the sandbox on start) and redeploy; the warning clears if it was stale. Only dig into server logs if it recurs on a genuinely fresh smoke.
- **2026-07-05 · apm-driver/outdated-auth** — A cockpit drift badge reading "unknown" while a manual `apm outdated` in the same repo says "up-to-date" is an **auth-context** difference, not a timing or parse-of-up-to-date bug: the interactive shell has the gh git-credential helper, a `pnpm dev` server may not (issue #108). → Don't re-diagnose it as timing or a parse flaw; check whether the server process can auth to the remote. The exact unreachable-remote output shape and how the parser classifies it (`reason: "unverified"`) live in `.claude/rules/apm-driver.md`.
- **2026-07-02 · tooling/rtk-masks-gh-checks** — `gh pr checks <n> --watch --interval 15` through the RTK hook did **not** block: it returned one canned snapshot (`Passed: 2 / Failed: 0 / Pending: 7`) and exited 0 while checks were still pending — a merge gate would fire on incomplete CI. → In workflow-ship, don't trust `gh pr checks --watch` under RTK. Poll `gh pr view <n> --json statusCheckRollup` in a loop until nothing reads `QUEUED|IN_PROGRESS|PENDING`, then read each `conclusion`. Same masking family as `tooling/biome-autofix-masked`.
- **2026-06-21 · web/styling-is-test-invisible** — The vitest/jsdom suite renders components with **no CSS**, so it is blind to styling: an invalid Tailwind utility name (I shipped `bg-app`, which doesn't exist — the surface utilities are `bg-canvas/bg-chrome/bg-card/bg-inset/bg-active`) silently no-ops and every test stays green. Also, before this slice the token CSS was wired **only into Storybook's preview** — the app entry (`main.tsx` + `index.html`) never imported `styles/theme.css`/fonts nor set `data-theme="dark"`, so the running app was fully unstyled while 100+ tests passed. → Never declare styled web work done on a green test run; run `pnpm smoke` and screenshot the page (agent-browser). Valid utility names are only those mapped in `styles/theme.css`.
- **2026-06-21 · web/storybook-vite8** — Storybook **8 and 9 cannot run on this stack**: `@storybook/react-vite@8` peers `vite ^4||^5` + `react ≤18`, `@9` peers `vite ≤7`; only **Storybook 10** (`@10.4.6`) peers `vite ^8` + `react ^19`. The "Storybook 8" wording in issue #78 / ADR-0004 is descriptive of the catalogue, not a version pin. → On this repo (Vite 8 + React 19), install `storybook@^10` + `@storybook/react-vite@^10`; never downgrade Vite to satisfy an older Storybook.
- **2026-06-21 · tooling/biome-tailwind** — Biome 2.4's CSS parser hard-fails on Tailwind v4 directives (`@theme`, etc.) with "Tailwind-specific syntax is disabled", which aborts `pnpm lint`. → Set `css.parser.tailwindDirectives: true` in `biome.json` whenever a `.css` uses `@theme`/`@apply`.
- **2026-06-21 · web/tailwind-theme-tokens** — Tailwind v4 `@theme inline { --color-x: var(--raw) }` makes utilities compile to `var(--raw)` directly, so a `[data-theme="light"]` override of `--raw` re-skins everything (the shadcn pattern). Theme-independent constants (radii/type/spacing) go in a plain `@theme {}` with literal values; do **not** self-reference (`--radius-tag: var(--radius-tag)` is circular). Verify utility generation with `pnpm dlx @tailwindcss/cli@4` + `@source inline("…")` (the `--content` flag is v3-only and silently ignored). → See `packages/web/src/styles/{tokens,theme}.css` for the split.
- **2026-06-15 · tooling/biome-autofix-masked** — `pnpm exec biome check --write <path>` printed the canned `Lint: No issues found` and did **not** modify the file; the real binary `./node_modules/.bin/biome check --write <path>` printed `Fixed 1 file` and applied it. `pnpm lint` (= `biome check .`) reported honestly throughout (it surfaced real `assist/source/organizeImports` errors with file:line). So RTK still intercepts `pnpm exec biome` **with `--write`** (no-op + canned line) — narrower than the masking the 2026-06-13 Archive entry retired. Also: `pnpm format` (= `biome format --write`) does not run the assist, so nothing in the `pnpm` scripts auto-sorts imports/exports. → To auto-fix import/export order, run `./node_modules/.bin/biome check --write .` directly; never rely on `pnpm exec biome --write`. Without that binary, sort by hand (bare modules before relative; `type` members sort by name among the rest).
- **2026-07-18 · apm-driver/symlink-skill-destination** — apm (measured on 0.20.0 and 0.25.0) refuses to deploy a skill whose *leaf* destination dir (`~/.claude/skills/<name>`) is a symlink ("is a symlink -- refusing to deploy"). Trap on 0.20.0: that failure still prints `Installed 1 APM dependency … with 1 error(s)`, so `INSTALL_SUCCESS_MARKER` matches — only `execFile`'s rejection on exit 1 catches it; 0.25.0 fails honestly (exit 1, "Installation failed", no marker). A *directory-level* symlink (`~/.claude/skills` → `~/.agents/skills`) passes on both versions, and apm's resolved-path dedup writes once for `-t claude,codex`. → For the symlinked-skills topology use one directory symlink, never per-skill leaf symlinks; full measurements in `docs/research/apm-0.25-symlink-topology-impact.md`.
- **2026-06-06 · testing/forbidden-headers** — The fetch-spec "forbidden headers" `Origin` and `Host` are NOT stripped by Node's undici on a manually-built `new Request(url, { headers })`, and survive through Hono's `app.request`. So the Origin/Host guard is testable end-to-end without a real socket: set `host`/`origin` headers directly. → Test write-route security via `app.request` headers; verify with a quick node probe before assuming.
- **2026-06-06 · core/tsconfig-node-types** — `packages/core/tsconfig.json` sets `types: []`, so the moment core legitimately uses a Node built-in (allowed behind a port — see `architecture.md`) typecheck fails with TS2591. → Keep `types: ["node"]` + `@types/node` in core's devDeps now the registry adapter uses `node:fs`.
- **2026-06-05 · apm-update** — A same-ref `apm install`/update silently overwrites local edits and drops untracked files in a deployed skill, printing `(files unchanged)`. `apm outdated` reports version drift only, never content drift. → When speccing J08 (update a deploy), warn before overwriting local changes. Detail in `.claude/rules/apm-driver.md`.
- **2026-05-30 · tooling/format** — The PostToolUse formatter is Prettier via `~/.claude/hooks/format-after-edit.sh` (local bin or `npx`), with no repo config → Prettier defaults: 2-space indent, **80-char width**, double quotes, semicolons. Biome at `lineWidth: 100` disagreed with Prettier's 80 and broke `biome check`. → In `biome.json` match Prettier: `indentStyle: space`, `indentWidth: 2`, `lineWidth: 80`, and Biome defaults for quotes/semicolons (don't set single/asNeeded). Biome's organize-imports assist is fine — Prettier doesn't reorder imports, so they don't fight.
- **2026-05-30 · tooling/pnpm** — esbuild's build script is ignored on install until allowed, which breaks vite/vitest; and the root scripts call nested `pnpm -r`, so `pnpm` must be on PATH. → Keep `allowBuilds: { esbuild: true }` in `pnpm-workspace.yaml`, and run `corepack enable` once (not just `corepack pnpm`) so nested `pnpm -r` resolves.
