## Active

Confirmed patterns. Apply as rules. Newest on top.

- **2026-07-28 · web/server-refusal-states-look-unreachable-in-smoke** — The remove dialog's server-refusal states read as unverifiable in a browser: `pnpm smoke` seeds no deployed skills, and producing one needs a real apm run with network and auth. Two facts make them reachable without apm: the deploy-state read is a plain `apm.lock.yaml` parse, and `claudeSkillName` takes the basename of `virtual_path` with no slug check while the removal use-case rejects the same name. A seeded entry with `virtual_path: skills/Not A Slug` therefore renders a row and makes the preflight answer a genuine `invalid-name` 400. Reconfirmed 2026-07-28 on #411: the recipe worked first try and produced the refusal screenshot the acceptance criteria needed. → To browser-verify a refusal state, seed a lockfile the reader accepts and the write path rejects; never skip the check as unreachable. Re-seed after every `pnpm smoke` start — it wipes the sandbox.
- **2026-07-23 · tooling/agentation-skill-omits-endpoint** — The vendored `agentation` skill (`.agents/skills/agentation/SKILL.md`, byte-identical to upstream) tells the agent to mount `<Agentation />` bare and then claims annotations "sync automatically"; they do not. Read from the shipped `agentation@3.0.2` types: without the `endpoint` prop the toolbar is localStorage-only, so `agentation_list_sessions` stays empty forever. `agentation-mcp doctor` prints "All checks passed!" regardless — it probes only the server, never the browser side. → Mount it as `<Agentation endpoint="http://localhost:4747" />`; confirm the wiring with `GET localhost:4747/sessions` (a session exists only when `endpoint` is set), never with `doctor`.
- **2026-07-22 · web/styling-is-test-invisible** — The vitest/jsdom suite renders without CSS, so an invalid Tailwind utility (e.g. `bg-app`) silently no-ops while every test stays green; the only valid surface utilities are those mapped in `styles/theme.css` (`bg-canvas/bg-chrome/bg-card/bg-inset/bg-active`). → Never declare styled work done on green tests; run `pnpm smoke` and screenshot with agent-browser.
- **2026-07-22 · web/storybook-vite8** — Storybook 8 and 9 cannot run on Vite 8 + React 19 (peer ranges); only Storybook 10 fits. The "Storybook 8" wording in issue #78/ADR-0004 describes the catalogue, not a version pin. → Install `storybook@^10` + `@storybook/react-vite@^10`; never downgrade Vite to satisfy an older Storybook.
- **2026-07-22 · tooling/biome-tailwind** — Biome 2.4's CSS parser hard-fails on Tailwind v4 directives (`@theme` etc.), aborting `pnpm lint`. → Set `css.parser.tailwindDirectives: true` in `biome.json` whenever a `.css` uses `@theme`/`@apply`.
- **2026-07-22 · testing/forbidden-headers** — Node's undici does not strip the fetch-spec forbidden headers `Origin`/`Host` from a hand-built `new Request(url, { headers })`, and they survive Hono's `app.request`. → Test the Origin/Host guard end-to-end by setting those headers directly; no real socket needed.
- **2026-07-22 · core/tsconfig-node-types** — core legitimately uses Node built-ins behind ports; with `types: []` typecheck fails (TS2591). → Keep `types: ["node"]` + `@types/node` in core's devDeps.
- **2026-07-22 · tooling/format** — The PostToolUse formatter is Prettier with no repo config, so Prettier defaults apply: 2-space indent, 80-char width, double quotes, semicolons. Biome at `lineWidth: 100` fought it. → Match Prettier in `biome.json` (`indentWidth: 2`, `lineWidth: 80`, default quotes/semicolons). Biome's organize-imports assist is safe — Prettier doesn't reorder imports.
- **2026-07-22 · tooling/pnpm** — esbuild's build script is blocked on install until allowed (breaks vite/vitest), and root scripts call nested `pnpm -r`. → Keep `allowBuilds: { esbuild: true }` in `pnpm-workspace.yaml`; run `corepack enable` once so nested `pnpm -r` resolves.
- **2026-07-18 · apm-driver/spike-isolation** — `apm -g` operates on `Path.home()` for both `~/.apm/` and `~/.claude/`; `apm uninstall -g` deleted 19 pre-existing skill dirs beyond its lockfile. The rule was violated once (2026-07-17): a real `apm install -g` ran against the real home. → Never run spike `-g` commands against the real home; redirect `HOME` to a throwaway dir, with `GITHUB_TOKEN=$(gh auth token)` and `GITHUB_APM_PAT` set.
- **2026-07-18 · tooling/rtk-masks-vitest** — `npx vitest run <file>` through the RTK hook printed a wrong summary (`PASS (25) FAIL (0)` for a run with 5 real failures); the direct binary reported honestly. Fixed 2026-07-26: every vitest form is listed under `[hooks] exclude_commands` in `~/Library/Application Support/rtk/config.toml`, verified by feeding the five invocation styles to `rtk hook claude` and getting no rewrite. That config is per-machine and unversioned. → Verify RED/GREEN via `./node_modules/.bin/vitest run ...`; on any machine whose rtk config lacks those exclusions, a bare `npx vitest`/`pnpm exec vitest` summary is still untrustworthy for a TDD checkpoint.

## Tentative

Single observations. Consider but do not auto-apply. Promote to Active on reconfirmation.

- **2026-07-22 · architecture/duplicated-invariant-drifts-across-sessions** — The J04 rule ("an uncheckable check is `unknown`, never `up-to-date`") and the behind↔deployed join are authored three times in `packages/web/src/drift/` (`drift-status.ts:29`, `target-drift-indicator.ts:35`, `derive-synced-state.ts:9`); per-job stateless sessions optimize local correctness and never consolidate across files. The tell: a comment saying "mirrored from skillDriftStatus" — a comment asserting two places agree documents a coupling that should be a dependency. → Before writing a derivation, type, or resolver that mirrors an existing one, give the invariant one owner (a shared type, a deep module, a named seam). Consolidate invariants, not code: the trigger is a fact that must stay in sync, not lines that look alike.
- **2026-07-20 · web/heading-rank-is-invisible-to-both-lanes** — Issue #222 shipped a mis-nested section with all headings at `h2`; 802 tests passed because every heading assertion omitted `level`, two review sub-agents and a smoke screenshot missed it too (identical visual weight reads as styling, not structure). → When adding, moving, or re-parenting a heading or section, assert `getByRole("heading", { level: n, name })` and read the resulting outline top to bottom.
- **2026-07-20 · web/per-row-hints-repeat-invisibly** — A conditional hint inside a per-row component rendered 36 times on the real inventory; component tests render it once, so presence assertions stayed green (#217). → Put list-wide hints on the list, not the row; assert the count with `getAllByText(...)`; screenshot before calling it done.
- **2026-07-20 · tooling/scripts-are-untypechecked-js** — Nothing in `scripts/` is typechecked (root tsconfig includes only tests; no `allowJs`), so a test importing `scripts/seed-sandbox.mjs` fails `pnpm typecheck` while `pnpm test` passes. Converting the script to TS is no fix: `dev.mjs` imports it under plain `node`. → When a test imports from `scripts/`, add a sibling hand-written `.d.mts`; no repo-wide `allowJs`, no promoting dev-launcher scripts to TypeScript.
- **2026-07-20 · apm/target-table-is-readable-source** — Issue #202's claim about which tools read `.agents/skills/` was unmeasured prose. apm ships a declarative target table at `apm_cli/integration/targets.py` (uv installs it under `~/.cache/uv/archive-v0/<hash>/apm_cli/`). Measured on 0.26.0: ten targets deploy skills under `.agents`, only `claude` and `kiro` elsewhere. → Treat issue prose about apm behaviour as a hypothesis; read the target table and record the measurement in `docs/apm-behavior.md`.
- **2026-07-20 · tooling/cwd-persists-and-hides-grep-errors** — Bash calls share a working directory (the global `workflow.md` claims otherwise), so a stale `cd` made `grep -rn ... packages tests` exit 1 with its `No such file or directory` swallowed by RTK — byte-identical to a clean no-match, and it became a false claim in a README. → Treat a no-output search as "unknown", never "absent"; use absolute paths or prefix the command with its own `cd`; echo `$?` before a zero-result becomes a claim.
- **2026-07-19 · apm/rich-wraps-phrases-mid-sentence** — apm's install output is Rich-rendered and hard-wraps mid-sentence (captured: `.../skills/tdd is` / `a symlink -- refusing to deploy`), so a literal `includes("is a symlink")` silently misses; the install path sets no fixed `COLUMNS`. → Match apm phrases against whitespace-normalized lowercase output; build fixtures from real captures, never retyped.
- **2026-07-19 · tooling/commit-gate-lints-whole-tree** — The commit-gate hook runs `pnpm lint` (= `biome check .`) over the entire working tree, so an untracked scratch file blocked a docs-only commit; `useIgnoreFile: true` does not skip untracked files. → When the gate fails on files outside your staged diff, check `git status --short` first; exclude the stray file class (e.g. `!**/prototype-*.html` in `biome.json`) or ask — never "fix" someone else's work-in-progress to get past it.
- **2026-07-16 · process/owner-cant-recount-it-its-dead** — The job map, roadmap, and coverage instrumentation grew past what the owner could retell from memory; a process artifact the owner cannot hold in his head is dead ceremony. Replaced by one board (`docs/jobs.md`) driven by the `jobs` skill. → A new process artifact, rule, or ritual must hang on a moment that already exists and be retellable by the owner; otherwise do not add it.
- **2026-07-13 · apm-driver/stale-sandbox-false-unverifiable** — A Global deploy showing `deployed-unverifiable` can be a stale smoke sandbox, not a live bug: the skill sits as a `name: home` apm project at HOME-root with `.apm-scratch` absent — a shape the current `-g` path never produces (verified: apm 0.20.0 lands cleanly in `~/.apm/apm.lock.yaml`). → Restart `pnpm smoke` (wipes the sandbox) and redeploy before chasing it as a code bug; dig into logs only if it recurs on a fresh smoke.
- **2026-07-18 · apm-driver/symlink-skill-destination** — apm (measured on 0.20.0 and 0.25.0) refuses to deploy a skill whose leaf destination dir (`~/.claude/skills/<name>`) is a symlink. Trap on 0.20.0: the failure still prints the install-success marker — only `execFile`'s rejection on exit 1 catches it; 0.25.0 fails honestly. A directory-level symlink passes on both. → For the symlinked-skills topology use one directory symlink, never per-skill leaf symlinks; full measurements in `docs/research/apm-0.25-symlink-topology-impact.md`.
