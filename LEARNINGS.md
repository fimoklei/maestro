## Active

Confirmed patterns. Apply as rules. Newest on top.

- **2026-09-18 · tooling/gh-api-sends-ids-as-strings** — `gh api -f sub_issue_id=$ID` (and `…/dependencies/blocked_by`) posts a string; GitHub answers 422 `… is not of type integer`, which reads as a wrong id. → Pass ids with `-F`, taken from `gh api repos/<owner>/<repo>/issues/<n> --jq .id` (database id, never the issue number).
- **2026-09-09 · tooling/smoke-binds-ipv6-only** — Under `pnpm smoke`, vite 8.2.0 listens on `[::1]` only, so `127.0.0.1:<web port>` is refused while the server is up. → Use the `localhost` URL `pnpm cockpit:url` prints; a refused web port is an address-family mismatch, not a dead stack.
- **2026-09-09 · tooling/vitest4-invocation** — On vitest 4.1.10, `--reporter=basic` is gone (`Failed to load url basic`) and `--root packages/core` breaks the root config's project globs. → Run one file as `npx vitest run <path-from-repo-root>`, no `--root`; `--reporter=verbose` for per-test names.
- **2026-09-09 · architecture/duplicated-invariant-drifts-across-sessions** — The J04 rule ("uncheckable is `unknown`, never `up-to-date`") is authored three times in `packages/web/src/drift/`; stateless per-job sessions never consolidate. Tell: a comment saying "mirrored from …". → Before mirroring a derivation, type or resolver, give the invariant one owner (shared type, deep module, named seam).
- **2026-09-09 · apm/rich-wraps-phrases-mid-sentence** — apm install output is Rich-rendered and wraps mid-sentence (`…/skills/tdd is` / `a symlink -- refusing to deploy`), so a literal `includes()` misses. → Match against whitespace-normalized lowercase output; fixtures from real captures only.
- **2026-09-09 · apm-driver/symlink-skill-destination** — apm (0.20.0–0.29.0) refuses a skill whose leaf destination `~/.claude/skills/<name>` is a symlink; 0.20.0 still prints the success marker. A directory-level symlink passes. → Use one directory symlink, never per-skill leaf symlinks. Measurements: `docs/research/apm-0.25-symlink-topology-impact.md`.
- **2026-09-04 · apm-driver/anonymous-probe-throttle-line** — apm 0.29.0 probes anonymously before using the token; once the machine's anonymous quota is spent, every install prints `GitHub API rate limit hit … skipping the pre-flight accessibility probe`, and a tokenless install then fails with auth phrases in install output. → Before capturing an install fixture, confirm the line is absent (`curl -sI https://api.github.com/rate_limit | grep x-ratelimit-remaining`); read it as machine state, never apm behaviour.
- **2026-09-04 · apm-driver/symlinked-home-deploys-nothing** — apm ≥0.29.0 `install -g` reports success and deploys zero files when `HOME` has a symlink component; macOS `tmpdir()` (`/var` → `/private/var`) is one. → `realpath` every sandbox `HOME` for `-g`; re-run with a resolved home before calling an empty global deploy a regression. Capture: `docs/research/772-apm-0.29.0-findings.md § F1`.
- **2026-09-03 · testing/coverage-project-flag-empties-the-report** — `vitest run --coverage --project <lane>` narrows the coverage root, so repo-root `coverage.include` globs match nothing: `Unknown% ( 0/0 )`, no warning (vitest 4.1.11). → Run `pnpm test:coverage` whole; for one lane, a throwaway root config with that single project. Capture: `docs/research/735-coverage-map.md`.
- **2026-09-01 · testing/red-needs-the-narrower-seam** — A journey test built on a real `git clone` went green before the fix (#668): git already writes the initial branch's tracking config, whatever `branch.autoSetupMerge` says (git 2.50.1). → When a new test passes before the fix, drop to the unit that owns the behaviour and build the fixture from `git init` + `remote add`; never bend the environment to force RED.
- **2026-08-09 · tooling/partial-commit-needs-add-first** — `git commit -- <paths>` on untracked paths fails `pathspec … did not match` (also on an unborn branch). → `git add -- <paths>`, then `git commit -- <paths>`; never fall back to a bare `git commit`, which sweeps up the user's staged work.
- **2026-08-06 · tooling/empty-repo-hides-its-default-branch** — On an empty repo `git ls-remote --symref <url> HEAD` prints nothing and exits 0; `git clone` does learn the unborn branch. `origin/HEAD` stays absent until `git remote set-head origin -a` (git 2.50.1). → Read the default branch from the clone (`git symbolic-ref HEAD`); call `set-head -a` after the first push. Capture: `docs/research/552-empty-repo-and-scaffold-shape.md`.
- **2026-08-06 · tooling/bare-remote-is-stricter-than-github** — Pushing a non-advertised branch into an empty repo: GitHub adopts it as default; a local bare remote leaves `HEAD` dangling (git 2.50.1). → A bare remote stands in for GitHub for clone, `origin/HEAD` and same-branch push only.
- **2026-08-03 · tooling/git-remote-get-url-resolves-inteadof** — `git remote get-url origin` applies `insteadOf` rewrites; `git config --get remote.origin.url` does not (git 2.51). → Show and identify by the configured URL; use the rewritten one only for where git will connect. The rewrite is also how tests give a temp clone an offline `github.com` origin.
- **2026-08-03 · tooling/smoke-home-redirect-kills-git-auth** — `dev.mjs --smoke` redirects `HOME`, so git has no credential helper and private https fetches fail `could not read Username`, while the same fetch works by hand. → Point the sandbox clone at a local bare mirror via `url.<mirror>.insteadOf <origin url>`; never call the fetch path broken from a smoke run alone.
- **2026-08-02 · deploy/bulk-consent-changes-hide-from-the-unit-test** — `bulk-remove-deployed-skill.test.ts` uses a fake remover, so tightening what `RemoveDeployedSkill` accepts stays green there; only `tests/integration/bulk-remove-journey.test.ts` caught #364. → When changing what a removal accepts, grep integration tests for hand-built `targets:` and mint receipts through `/api/deploy/remove/preflight` (`entriesFor` in `server-bulk-remove.test.ts`).
- **2026-08-02 · tooling/smoke-home-redirect-hides-corepack** — The redirected `HOME` gives corepack a cold cache, so every start re-downloads pnpm: an interactive hang, or `getaddrinfo ENOTFOUND registry.npmjs.org` that reads as a network bug. → When redirecting `HOME`, carry `COREPACK_HOME` over and set `COREPACK_ENABLE_DOWNLOAD_PROMPT=0`.
- **2026-07-28 · web/server-refusal-states-look-unreachable-in-smoke** — The remove dialog's refusal states look unverifiable without real apm. The deploy-state read is a plain lockfile parse, and `claudeSkillName` takes `virtual_path`'s basename unchecked while the removal rejects it. → Seed an entry with `virtual_path: skills/Not A Slug` for a real `invalid-name` 400; re-seed after every `pnpm smoke` start.
- **2026-07-27 · apm-driver/ref-subpath-is-literal** — An apm ref's subpath is literal: `github.com/o/r/skills/tdd#v…` fails `Subdirectory … not found` when skills live in `.apm/skills/`, though apm reads both shapes from disk (0.26.0, 0.29.0). → The harness's skill path reaches `buildSkillPackageRef` as data, fixed per tag.
- **2026-07-27 · tooling/git-config-key-channel-survives-isolation** — apm's `GIT_CONFIG_GLOBAL=/dev/null` leaves the `GIT_CONFIG_COUNT`/`KEY_*`/`VALUE_*` channel intact, so an `insteadOf` set there redirects every apm install. → Use it to measure GitHub-shaped installs offline; `GIT_CONFIG_GLOBAL` alone proves no git-config isolation.
- **2026-07-27 · apm-driver/compile-overwrites-owned-context-files** — Plain `apm compile` overwrites `AGENTS.md`/`CLAUDE.md` in `$PWD` with a generated build; `--user-scope` does the same to `~/.claude/CLAUDE.md` (0.26.0, re-read 0.29.0). → Only `--validate` and `--dry-run` are safe here.
- **2026-07-27 · apm-driver/validate-is-not-a-validity-signal** — `apm compile --validate` never reads `skills/*/SKILL.md` and reports `All primitives validated successfully!` over broken skills; `apm install` normalizes a bad name and exits 0 (0.26.0, re-read 0.29.0). → Check structural skill rules in `core`. For hidden Unicode, `apm audit --file <path> -f json` and read `passed`, never the exit code.
- **2026-07-23 · tooling/agentation-skill-omits-endpoint** — The vendored `agentation` skill mounts `<Agentation />` bare, which stays localStorage-only (agentation 3.0.2); `agentation-mcp doctor` passes regardless. → Mount `<Agentation endpoint="http://localhost:4747" />`; confirm with `GET localhost:4747/sessions`.
- **2026-07-22 · web/styling-is-test-invisible** — happy-dom renders without CSS, so an invalid Tailwind utility (`bg-app`) no-ops with every test green. Valid surfaces are those mapped in `styles/theme.css` (`bg-canvas/bg-chrome/bg-card/bg-inset/bg-active`). → Use only mapped utilities; prove styling with a smoke screenshot.
